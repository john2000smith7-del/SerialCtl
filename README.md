# SerialCtl

SerialCtl 是面向 Windows 的原生 C++17 / Win32 串口与远程终端工具。

当前源码版本：`V2.0.15`。生产程序不依赖 .NET Framework，使用 `/MT` 静态运行库，并以 Windows 7 SP1 为最低系统版本。正式便携包须通过 MSVC 与 Windows 兼容性检查后生成。

## 主要功能

- Windows 7 SP1、Windows 10、Windows 11，仅提供 x64 程序。
- 本地串口终端；串口打开后可通过 WebSocket `7000–7015` 中可用端口在可信内网共享。
- 发现并连接其他 SerialCtl 已打开的串口，同一 WebSocket 会话服务容量上限为 128 个客户端（不等于性能测定），慢客户端会被隔离断开。
- Telnet 和 SSH；SSH 使用随包提供的定制 PuTTY `plink.exe`。
- SSH 会话的 SFTP 文件浏览、排序、多选、上传、下载、取消、重试和文件管理。
- 多会话切换，每个会话独立保存终端、滚动、编码、日志和 SFTP 状态。
- 主屏幕逻辑行重排与 CMD 本地行编辑；VT/xterm 终端，支持 ANSI 16/256/RGB 色彩、备用屏幕、宽字符、bracketed paste 和 20,000 行回滚。
- UTF-8、GBK、GB2312 编码，以及独立时间戳栏、选择、复制、粘贴、滚动和字体缩放。
- 可编辑命令笔记、当前行/完整选中行运行、正文双击运行、批量提交/停止、TXT 拖入及导入导出；实际执行结果见终端输出。
- 默认浅色主题，支持深色切换；设置位于右上角齿轮，左侧连接列表采用会话侧栏图标；桌面图标保持原样。
- 终端拖选完成自动复制、右键直接粘贴；顶部“设置”集中管理原终端菜单功能，明确全局与当前会话作用域。
- 保留 IT6332A 电源面板与实时终端布局；本版禁用电源连接及操作，USB/VISA、RS232、AI 和远程接口均无法操作电源。
- 本地 CMD 与自动启动的固定范围 AI 接口；支持 Linux 客户端与二进制安全的 WebSocket v1。
- 发布包包含 Win7 NI-VISA 18.0 Runtime 完整离线安装文件。
- 可配置内网自动更新：每次启动后台检查，签名验证后在空闲时更新；保留配置、命令、日志与驱动。

## 使用

### AI 智能串口助手

连接成功后，AI 在空白对话中介绍高级嵌入式软件工程师助手的定位与能力，不公开内部角色名，不自动发送设备命令；重连已有对话时不重复介绍。AI 消息支持拖选文字、松开即复制，保留整条消息复制；顶部不重复显示名称或角色副标题。页面以两端留白细线划分统一底色区域。顶部 AI 页面使用中间原终端区域进行对话，底部内部提供紧凑多行输入与发送/停止，目标收起时仅显示类型和端口；用户消息与选中项使用深蓝色，AI 回复采用独立中性卡片，支持上下滚动查看历史。连接 Linux Codex 服务器后复用其默认模型配置，不再提供模型选择；无需在 Windows 安装 Codex 或重复填写网关密钥。AI 背景沿用更浅的灰色主题面板，用户消息使用深蓝色强调。

AI 与所选终端实时监视区默认五五开，同时显示；拖动间隔调整比例，双击恢复等分，独立保存比例及收起状态。监视区默认隐藏程序时间戳，按原始硬换行显示长行并支持底部横向滚动；点击“长行查看／自动折行”切换，交互终端的远端尺寸与备用屏幕规则保持。它复用实际终端，支持原有滚动、选择、复制及输入。

工作空间按当前目录列出子目录；上一级返回父目录。单击路径栏查看完整路径，超长路径用底部横向滚条查看；双击可编辑，Ctrl+C复制完整值。左侧连接栏可通过标题图标收起/展开，记住状态且不影响现有连接。

连接设置可填写“服务器项目目录”（Linux 绝对路径，如 `/srv/projects/board`，留空使用服务器默认目录）。AI 可通过 Codex 原生工具读取、修改该 SSH 用户可访问的服务器代码并运行服务器命令，对话显示命令输出、退出码及文件差异。代码须位于容器内或已挂载的可访问路径；不会因此自动取得其他主机或容器外文件访问权。

关联终端由用户明确选择，支持已连接的本地/远程串口、CMD、Telnet、SSH。可在输入栏选择“连接远程串口…”，填写远程 IP、查询并选择该主机已经开放的串口；不默认选择本机 COM。AI 可以读取实际输出，并直接通过所选终端连接提交匹配其系统的单行诊断命令，不再逐条二次确认，执行结果以设备回显为准。当前范围不新增多客户端写入仲裁。远程串口仅发现 SerialCtl 自身的 WebSocket 服务及其已打开串口；保留自动查询 7000–7015 和高级指定端口。弹窗只提供 IP、刷新与串口选择，不提供 UDP 识别、候选或连接入口。未发现服务或串口时保留真实错误，不允许连接。

进入启动固件提供U-Boot连续空格和飞腾UEFI连续F2两套内置预设，按板卡连接保存选择。AI先确认目标串口、实际系统和登录状态，再提交一次reboot（reset仅用于已确认的板卡复位命令）；客户端立即发送首个按键，之后按300ms（可500ms）间隔连续发送，不等待启动关键词、不限制发送次数，默认持续至实际目标提示/菜单、停止或断线；可显式设置超时。VT100/VT100+ F2编码需与现场UEFI串口类型匹配；不能将受控输出测试等同真实板卡验收。

本版按交付要求禁用电源功能。电源连接仅显示“该功能暂未开放，请等待后续开放。”，不枚举或打开设备；服务层在排队前拒绝所有电源操作，AI 与远程接口不能绕过。电源状态机和受控仿真测试保留，供后续开放前验收。

SSH 密码认证失败时只清除当前 AI 服务器账号保存的旧密码，允许重新输入；主机身份记录保留，密码变化不应删除主机指纹。历史会话可搜索恢复；执行时过程默认折叠，只保留独立最终回答及可展开的过程摘要；中间命令失败会在摘要标明“含失败记录”，原文仍可展开查看。整个任务失败或被停止时继续折叠，摘要明确标出结果。恢复历史沿用同一规则，兼容服务器未标注过程消息类型。会话上下文由服务器端 Codex 管理，可在历史弹窗请求“整理当前会话”；不支持时保留原会话，不把界面折叠或显示上限当作压缩成功。

实现、凭据与兼容边界见 [AI 架构说明](docs/architecture/AI-ASSISTANT.md)，正式发布前需完成 [AI 验收](docs/testing/AI-ASSISTANT-ACCEPTANCE.md)。本段不代表已通过现场 SSH、模型网关或 Win7 硬件验收。

V2.0.3 比 V2.0.2 高一个补丁版本。新版本客户端在可信新版提示中仅提供“确定”，确认后下载并验证更新，完成后安装重启；关闭提示退出。V2.0.2 客户端首次升级到本版本仍使用旧版已有的自动更新行为，安装后才采用新提示流程。

### 本地串口与共享

1. 点击顶部“串口”。
2. 选择 COM 口、波特率和流控。
3. 点击“连接”。程序启动即提供统一服务，自动选择 `7000–7015` 可用端口；每个已打开串口注册为明确的会话。
4. 根据现场安全策略配置 Windows 防火墙。

共享串口没有认证、加密或写入互斥，只适合操作者可控的可信内网。多个客户端同时写入时，需要自行避免命令交叉。

### 连接其他电脑的串口

1. 点击“远程串口”。
2. 输入来源电脑的 IP，自动发现共享端口。
3. 自动查询，也可手动刷新远端串口列表。
4. 选择串口并连接。

### SSH 与 SFTP

AI 页提供鲸鱼娘宠物：打开后约 4 秒播放三次前后跳步和拳击，随后跟随 AI 的思考、工具、回复和完成状态。默认桌面悬浮，拖动可跨窗口移动，主窗口最小化和切换页面后继续显示；右键可打开主窗口、返回窗口内、播放动作、调整大小、收起或进入设置。设置可关闭开场播放或置顶，位置和偏好保存在现有 `settings.ini` 中。正常主窗口在同一 Windows 用户会话内只运行一个实例，重复打开唤回原窗口。

首次连接未知 SSH 主机会显示指纹。请通过管理员等独立渠道核对后确认；确认结果持久保存到当前用户注册表。服务器密钥变化时展示旧、新完整指纹；勾选已通过可信渠道核对后才能更新该服务器身份并重新连接。SSH 与 AI 连接弹窗都提供“重新核验主机”，更新同步清除该服务器旧内存缓存，无需重启。取消、未获取到指纹或新指纹再次变化时保留原记录；不自动重发 AI 或终端指令，不清空其他主机及外部 PuTTY 的身份记录。

SSH 登录成功后，右侧 `SFTP` 页会自动读取目录。路径面包屑、排序、多选、拖入上传、传输队列和文件操作均使用同一 SSH 主机信息。

SSH、SFTP 和主机验证统一通过仅限当前用户及 SYSTEM 的本机一次性命名管道向 PuTTY 传递密码（`-pwfile`），密码不进入命令行或临时文件。也可使用 PuTTY 已保存的密钥配置或 Pageant。

命令笔记只有一个运行入口，按钮/行旁图标在内部松开后提交，拖出可取消；相同发送计划在系统双击时间内合并，停止不受此限制。正文双击执行该行默认开启，可在更多菜单关闭。AI 的“停止”使用独立按钮，忙碌时再次点击“发送”不会停止任务。`Ctrl+F6` / `Ctrl+Shift+F6` 在可见窗格之间移动焦点；终端原有功能键和 Tab 仍传给设备。编辑框统一支持 `Ctrl+A`。

### 日志与命令

会话日志默认写入：

```text
%LOCALAPPDATA%\SerialCtl\logs\
```

命令笔记保存到 `%APPDATA%\SerialCtl\command-notebook.txt`，首次从旧 `commands.txt` 带入内容，旧文件保留。直接编辑或拖入 UTF-8 TXT，运行按钮发送当前行或选中涉及行的完整命令，空行/注释跳过；正文双击运行默认开启，可在文件栏更多菜单关闭。支持 Ctrl+Enter、保存、导入/导出和统一滚动条。批量发送的运行按钮变为停止，只取消后续发送；换会话/断线即停止，不自动重发。更多菜单设置发送间隔。

## 内网自动更新

编辑 `serialctl.exe` 旁的 `update.ini`，在 `[update]` 下填写 `url=完整的 update.json 网址`。V2.0.2 默认填入用户确认的 `http://172.16.3.188/external/serial/update.json`；后续地址变化只改这个文件。程序每次启动读取配置，服务器不可达时继续使用当前版本。正在使用的设备和任务不会为更新而被强制断开。

V2.0.0 起，每次交付两个文件：完整发布 ZIP 和内嵌数字签名的 `update.json`。管理员直接上传到同一静态目录，无需生成签名、拆分运行文件或维护额外 `.sig`。程序启动自动检查，验签并确认存在更高版本后提示用户，点击“确定”才下载整个 ZIP，只替换批准的运行文件，保留配置、日志和驱动；旧版首次切换需要手动部署一次 V2.0.0。使用步骤见 [AUTO-UPDATE.md](docs/package/AUTO-UPDATE.md)，签名封装及发布门槛见 [架构说明](docs/architecture/AUTO-UPDATE.md)。

V2.0.4-r1 恢复 V2.0.0–V2.0.3 使用的原签名身份。原 V2.0.2 客户端可直接自动升级到本修订，无需经过中间版本；服务器仍只替换配套 ZIP 和 update.json。曾手动安装新公钥版 V2.0.4 的客户端不属于这条原信任链，且同为 V2.0.4 不触发自动更新。

目录按真实职责创建，不使用空目录或占位文件表示未来能力。

## 构建与测试

在 Visual Studio C++、Windows SDK 和 CMake 已安装的开发环境中执行：

```powershell
.\scripts\build.ps1 -Architecture All -Configuration Release -Clean
.\scripts\test.ps1 -Architecture All -Configuration Release
.\scripts\check.ps1 -Architecture All -Configuration Release
```

也可以直接使用 CMake：

```powershell
cmake -S . -B .\build\windows\x64\cmake -A x64
cmake --build .\build\windows\x64\cmake --config Release
```

CMake 会从 `third_party/yy-thunks/yy-thunks.1.2.1.nupkg` 临时解出所需兼容对象，不要求源码树保留展开后的依赖构建目录。

## 发布包

正式本地发布入口：

```powershell
.\scripts\release.ps1
```

构建流程会重新构建并测试 x64，检查 PE 架构、文件版本、子系统版本 6.01 和禁止依赖，生成固定白名单内容，压缩后重新解压并核对 SHA-256。成功后 `bin` 中保留完整 ZIP；正式签名完成后，交付其配套 `update.json`：

```text
SerialCtl-V2.0.15-Win7-x64.zip
update.json
```

压缩包根目录直接包含 x64 的 `serialctl.exe`、`plink.exe` 和 `psftp.exe`，解压后保持三者位于同一目录。

## Windows 7 兼容策略

- `WINVER`、`_WIN32_WINNT` 和 `NTDDI_VERSION` 固定为 Windows 7。
- 主程序及辅助程序 PE 子系统版本固定为 `6.01`。
- 使用 `/MT`，发布程序不依赖 Visual C++ Redistributable。
- 使用 YY-Thunks 处理新工具链可能引入的兼容调用。
- SSH/SFTP 使用定制 PuTTY 0.85，补丁和复现说明位于 `third_party/putty/`。

编译与导入检查不能替代真实 Windows 7、USB 转串口硬件和现场 SSH/SFTP 环境验收。人工测试步骤位于 `docs/testing/`。

## 已知边界

- 共享串口只适合可信内网，不提供认证、加密或写入互斥。
- 终端覆盖常用 VT100/xterm 行为，少见图形协议和部分专有扩展未实现。
- 真实 Win7 驱动、长时间大流量、具体 SSH 算法及服务器 SFTP 子系统需要现场验证。
- `legacy/csharp` 是历史 WinForms 原型，不属于生产程序或发布包。
