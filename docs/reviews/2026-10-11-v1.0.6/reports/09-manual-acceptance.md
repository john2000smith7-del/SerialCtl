## 0. 准备、隔离与统一记录

1. 准备 Win7 SP1 x64 实机或完整桌面VM、Win10/11对照；记录系统版本/补丁、CPU/RAM、显示器/分辨率/工作区、DPI、字体、显卡与驱动。不额外安装.NET或VC Runtime来掩盖便携包依赖；测试采集工具的依赖单独记。
2. 完整解压候选 ZIP 到独立目录；`serialctl.exe/plink.exe/psftp.exe` 同目录，不拿开发输出替换。保存 ZIP、MANIFEST.json、全文件清单；使用系统 `certutil -hashfile "包路径.zip" SHA256` 及同法对三个 EXE 求哈希，记完整源码SHA。候选ZIP SHA可与总报告核对，但不把ZIP SHA当EXE SHA。
3. 测试只在专用实验网络、回环串口与测试SFTP目录进行；真实电源使用受控测试负载，先记录允许电压/电流和人工断电方式，避免把实际业务负载当故障注入对象。明确每个 COM 的物理接线/回环方式与硬件串号；COM3/COM5以下仅作示例，应替换现场值。
4. 建证据目录 `case-id/`，保存环境JSON/文本、屏幕录像、原始RX/TX、客户端日志、SCPI/action结果、进程清单和CSV。不在证据中保存密码。所有时刻用UTC并注明时钟同步误差；每一步结果只填通过/失败/未运行/阻塞，缺设备写具体原因。
5. 提前记录本版明确边界：CMD是行提交桥接，Ctrl+C/全屏交互受限；网络CMD等同当前用户shell能力；无任务级互斥；queued不是执行成功；断线未知不自动重发。用这些边界设计预期，不能将既定范围误判为接口越权。

## 3. 本次产品边界复验（P-01～04）

- **宏完成**：两步 `ping -n 11 127.0.0.1 >nul`、`echo MACRO_DONE`，短间隔执行；录像同时保存实际输出时刻。第二轮设5秒间隔，第一步运行时Stop。通过标准：最后入队只报告已提交，不伪称执行完成；Stop明确后续提交停止，已提交任务可继续。
- **尾行丢失**：先在CMD留下草稿 `echo PRESERVE `，再从专用文本文件复制 `SAFE`+CRLF+8192个x；保存原草稿/光标，粘贴后检查实际TX与草稿。仅用无害echo前缀，勿重试整批命令。再测8190/8191、CR/LF/CRLF、光标中部、前缀被拒绝及编码不可表示。通过标准：拒绝不产生前缀TX，草稿光标可恢复；若设计允许部分提交，则必须有明确确认和可恢复尾稿。
- **后台错误**：打开A/B，保持B活动，对A拔线/拒绝连接，切回A；检查最近错误原因与来源，B不受污染。32会话下重复刷新、滚轮、Home/End/Page、物理拖滑块，锚点与选择不跳。
- **电源断开反馈**：按第6节先受控backend故障再实机。区分Submit直接拒绝（应已提示）与接收后OFF/OUTP?失败（候选反馈丢失）；保留action ID与unknown证据。

## 4. 双AI、实体UART、多COM与真实LAN（SER/LAN-01～06）

1. Win7本地打开两路已接线串口，记录波特率、8N1/流控、驱动/固件、物理拓扑；第二台Linux通过有线LAN使用随包Python，第三客户端用SerialCtl远程COM。先 `python3 serialctl_client.py <WIN_IP> list`，再分别 `watch COM3`；显式端口/instance依随包 `--help`，记录发现结果。
2. 独立对端先验证回环接线，然后在GUI关闭并重新打开待测COM，建立无历史输出的新resource；停止其他写者，确认设备静默后再使用随包库跑以下**单次样本**（环境变量替换实际IP/COM，Python在含随包模块的目录运行）。这避免SerialStream的历史订阅把前次输出误算成本次RX。流控须允许全字节，专用链路不得混入其他设备输出：

```python
import os, hashlib, json
from serialctl_client import SerialStream
payload = bytes(range(256)) * 64  # 16384 bytes，低于每次输入65536
with SerialStream(os.environ['SERIALCTL_TEST_IP'], os.environ['SERIALCTL_TEST_COM'], timeout=30) as stream:
    accepted = stream.send(payload)
    rx = bytearray()
    while len(rx) < len(payload):
        rx.extend(stream.recv(len(payload) - len(rx)))
open('tx.bin', 'wb').write(payload)
open('rx.bin', 'wb').write(rx)
print(json.dumps({'accepted': accepted, 'tx': len(payload), 'rx': len(rx),
    'tx_sha256': hashlib.sha256(payload).hexdigest(),
    'rx_sha256': hashlib.sha256(rx).hexdigest(), 'equal': bytes(rx) == payload}))
assert bytes(rx) == payload
```

该例只验证发送者回环；两AI/桌面订阅者需各保存原始接收字节并核对同一轮样本。多写者使用带来源、序号、长度和校验的完整批次，接收端按实际序列比较；只要求批次内不交叉，不要求多步任务互斥。COM5用另一标记流验证无串流；关闭COM3后COM5继续。

3. 核对NUL/FF/CRLF、UTF8/GBK逐字节、握手后立即输出、启动输出。旧TCP/Telnet控制、Ping/Close不得写UART；合法FF不可过滤。记录真实framing/parity/overrun与ClearCommError，照片乱码不单独判根因。
4. 测端口占用/不存在/未打开、拔设备、断LAN、恢复。先占7000再启动验证回退；专用机占7000–7015验证本地CMD/UART仍可用；两实例发现歧义后指定实例；重启后旧instance拒绝执行。保留错误JSON及设备实际写入计数，未知请求不得自动重发。
5. 1/2/8/32客户端逐级负载，每级另加停止读取客户端；健康端、原始日志与GUI继续。容量128/第129行为测试仅在受控独立环境执行，不能把容量当性能承诺。核对完整RX/TX和重连后无意外重复执行。
6. 延迟分测：Publish→完整客户端消息、PostData→BitBlt、外部录像/相机物理呈现。跨机用同步时钟并记误差，或同机回环往返报告RTT，不能简单除二当单向。每级写样本数、UART线速、字节/包、客户端数、P50/P95/P99/最大值、超时/丢失。10ms转发/50ms显示是优化目标，不填作未测承诺；物理UART传输时间与应用新增时间分开。

## 5. 真SSH/SFTP与数据完整性（SFTP-01）

- 使用真实测试服务器、专用账号和唯一目录，首次指纹由独立渠道核对；分别拒绝/信任，密钥变更必须警告。保留服务器/PuTTY版本与连接日志，不记录口令；不能用mock代替。
- 生成小/大文件、中文/空格/长文件名、零字节文件，记录本地SHA256；上传/下载与覆盖取消/确认、多选、路径跟随/手动浏览、排序、列宽重启逐项执行。服务端 `sha256sum` 对照原始文件；本地用certutil/Python。
- 大文件中途取消、拔网络、关闭原SSH会话、全部断开、退出。检查状态、重试归属、远端文件/临时文件是否存在及大小/哈希；取消的文件不能仅凭“取消”标签当完整。恢复后显式选择重试，确认不隐式转到新会话/目录。
- 通过标准：成功文件哈希一致、覆盖有确认、失败/取消准确且可诊断、取消/断开后无遗留psftp传输；原连接断开后的禁止重试提示符合现有边界。远端不完整文件的处理与提示记实，不自行认定已回滚。

## 6. IT6332A实际USB/RS232与安全收尾（PWR-01～04）

1. 记录设备型号/序号/固件、USB或RS232、NI-VISA18现有离线驱动、仪表及接线；无设备写未运行。先由人工确认安全测试电压/电流，记录CH1/2/3初始状态；GUI只选1/3，2保持独立状态。
2. GUI和网络总ON/OFF只影响1/3；抓请求/action轮询/SCPI及仪器实测。网络尝试电压/电流/模式/通道替换/保护/预设/复位/SCPI/任务，必须前置拒绝且设备计数无写入；**不使用允许的任意CMD去绕行操作系统做“API越权”演示**。
3. 本地模式/保护/预设/任务与监测编辑：聚焦及跨字段未提交草稿，等待刷新/异步完成，草稿不能意外覆盖。任务仅拥有指定通道；Stop、全部断开、正常退出只尝试关闭任务拥有通道，非任务通道保持。总OFF的GUI选择范围和任务Stop的拥有范围分别记。
4. 先受控backend延迟worker、填满128合法动作，再分别OFF/stop/disconnect，检查安全动作仍可入队、旧ON取消；不得直接向真实负载灌128条加电。另在已接收断开后制造OFF/OUTP?失败，保存action与state.error、unknown以及主窗持久警告。实机再用受控拔通信线/超时验证：软件不得声称已掉电，恢复后由仪器实测并人工确认，不盲目自动重发。
