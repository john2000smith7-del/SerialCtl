# 独立测试脚本复核（2026-10-16）

审核者：独立子代理 paint_test_review。范围为新增 `gui_paint_user_actions.py`、`gui_theme_user_actions.py` 以及调用的 `DesktopActions` 方法、原生取色和终端只读测量属性。仅审阅源码与既有原始图片；本审核者未声称本地 Linux 执行了 Windows GUI。

## 结论与需修正项

1. **确定缺陷，主题脚本列表读取接口误用。** 初稿调用 `self.read_message(self.control(106), 0x18b)`，而基类签名是 `(message, lparam=0)`，目标固定为主窗口，返回 `(result, elapsed_ms)`。因此既没有读取列表 LB_GETCOUNT，又把测量耗时带入前后值比较。应直接对列表 HWND 发只读 `SendMessageTimeoutW` 并仅比较结果。
2. **确定的输入语义风险，主题快速同点点击。** 初稿主题点击间隔约130ms，会进入系统双击时间。源码 `ButtonSubclassProc` 只对侧栏125把 `WM_LBUTTONDBLCLK` 转为普通按下；主题104是原生 owner-draw button，可把第二次点击变为双击通知。主题测试应等待大于 `GetDoubleClickTime()`，避免用未被应用的第二次点击误判主题刷新。
3. **采集同步应补全。** 两个新增采集路径 `BitBlt` 后直接读取 DIB 内存。根据 CreateDIBSection 的同步要求，应在该采集线程调用 `GdiFlush` 后读取位，避免将尚未完成的 GDI 绘制当作最新屏幕帧。该调用只同步测试采集 GDI，不向程序发送重绘消息，不会掩盖应用残影。
4. **阶段首帧不等于动画中间帧。** `ScreenRecording` 初稿在输入前设置 phase，每个 normal-* 阶段仅保存第一张 PNG。因此这些 PNG 可能仍属于前一稳定状态。应从完整无损 MKV 按 JSONL 实际时间提取点击释放后约40/100/180/240ms帧复审，或额外保存中间样本。

上述前三项已即时发给主代理修正；本报告暂不将未复查的修改写成通过。

## 首次运行取消点击失败的独立定位

Windows 运行 `38854535904` 在20次主题切换后，取消“全部断开”按压时出现会话列表变化。仅凭日志尚不能判断为产品缺陷。源码主窗口 `WM_COMMAND` 对该按钮仅接受 `BN_CLICKED`，未发现把焦点/其他通知当点击执行的路径。测试在 `SetCursorPos` 外移后立即释放，仅证明全局鼠标位置已变，没有证明目标按钮已经处理异步 `WM_MOUSEMOVE`。原生 BUTTON 依赖自身按压状态，在此输入时序下可能仍激活。

建议保持会话数断言，增加只读 `BM_GETSTATE (0xF2)`：记录按下时 `BST_PUSHED=4`，外移后等待该位清零并保存实际时延，再释放。如果窗口不能在合理等待内清除按压状态，则记录并继续作为产品交互问题调查；不能删除断言把失败改成通过。最终归因待原始 JSON/图像和后续实际窗口运行。

首次运行原始 JSON 已复核，SHA-256 `3365477bc0a8cca5f75a92aeeb5298a2ff819d4013606a755ef094b76ea33ce6`：20次主题切换的所有 early/settled 取色匹配率均100%，hover/pressed 取色也100%；取消按压后会话数由2变0。输入轨迹记录外移为15.085451秒、释放为15.085666秒，间隔0.215ms。这支持“未等待原生按钮处理移动”的时序候选，但该 JSON 没有当时原生按钮状态，不能单凭间隔最终归因。

已复核后续提交 `3a4fa759310b133b5ce8031cd4cca4598a63ffe6`：只新增 `BM_GETSTATE` 读取和最长1秒的真实状态等待，保留全部会话数断言，并增加释放前会话数、外移命中 HWND、按下及外移状态、等待毫秒数。没有发送 `BM_SETSTATE`、`WM_CANCELMODE` 或其他人为取消消息，属于修正输入操作的可观察性，不是删除失败断言。后续实际运行仍需验证。
