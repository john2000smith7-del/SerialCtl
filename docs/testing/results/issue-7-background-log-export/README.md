# Issue #7：固定截止点的后台日志导出

原始确认范围是 UI 同步复制且复制阶段占用 logger 锁；真实慢盘数据丢失、无限挂起仍属候选。
本轮基点为 main `a9f17ee972041345aa5b26790a6de4140ce7edaa`，生产改动 `7fe37d30c782fb99b8cf75831841e332efe247cf`。
VERSION 仍为 V1.0.8；没有发布新版安装包或更改现场二进制。

## 实现范围

- `SessionLogger::CaptureExportPoint/CaptureSnapshot/CopySnapshot`：保存确认时捕获 generation、根路径和已接收字节数。
  等待固定截止点写完时释放生产者锁；分卷路径和有效长度在短锁中冻结，复制、目标刷新和替换均不持 logger 锁。
  后续写入、轮转和 Stop 不延长快照，不混入新会话；已知源日志错误明确拒绝导出。
- `MainWindow::StartLogExport/PollLogExport/CancelLogExport/StopLogExport`：单个后台任务持有会话 logger；
  电源日志与 CSV 通过同一任务导出。工作线程不捕获 MainWindow 指针，不向 UI 发送拥有堆内存的完成消息。
  源所有权释放后才发布完成，避免正常完成时 UI join 等待 logger 析构。
- Settings 的实例级“取消日志导出”在没有当前会话时仍可用；进度/结果在说明行保留，悬停显示完整内容。
  重复导出禁用，其他设备控制保持可用；导出信息不覆盖已有错误、宏未知结果或新的用户状态。
  100% 仅表示复制完成，刷新/替换结束后才显示已保存。底部“取消”只取消设置草稿。
- 同目录 CREATE_NEW 临时副本、精确长度读取、刷新后 MoveFileEx 替换；取消、读取失败、目标失败保留原目标，
  清理失败明确报告临时路径。目标错误不写入源 logger 的 failure。防止覆盖源根文件、当前和未来 partN 分卷。
- 退出先请求取消，设备/传输关闭先于等待导出回收；安装更新把导出视为忙碌。
  CancelSynchronousIo 和分块取消覆盖普通可取消 I/O；不承诺所有故障驱动/网络提供程序都能在固定时间返回。

## 验证方法和边界

`tests/integration/SessionLoggerTest.cpp` 编译生产 logger，仅测试目标启用写失败注入：
65 MiB 全 A 数据跨 64 MiB 轮转，复制到 64 KiB 后用 condition_variable 挂起导出；
真实生产者追加 1 MiB B，Stop 在导出挂起时结束，最后导出长度和预先计算 SHA-256 精确等于原 65 MiB。
另覆盖部分复制后取消、预取消、受控 ERROR_DISK_FULL、实际只读替换失败、目录不存在、截断源、
旧 generation、空 CSV、源/当前/未来分卷保护、临时清理及失败后正常记录/导出。
这属于原生受控本地文件测试；故障注入不等于物理磁盘满或真实 SMB 掉线。

`tests/integration/gui_log_export.py` 在两主题的实际打包程序中，通过既有 CMD 输入操作提交无害 REM 批次，
配合当前会话原始字节日志生成至少 65 MiB；实际鼠标进入 Settings、原生 Save As，键盘输入保存路径。
只读可选 UI 指标观察截止点和忙碌；源实际文件分卷的截止点前缀重算 SHA-256，与导出文件独立核对。
另一健康客户端和 WM_NULL 测实际响应，并记录是否真的观察到忙碌重叠；本地复制可能很快，不能把零重叠样本说成限速 UI 验收。
同时核对导出结果不会遮蔽已有 CMD 错误、任务完成后的取消禁用、设置说明行和原生弹窗焦点。
截图从可见桌面 BitBlt 获取，保存在 Actions artifact；截图尚需独立视觉复审，不能据脚本 PASS 声称无闪烁。
