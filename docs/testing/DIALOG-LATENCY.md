# 连接弹窗首帧与后台查询验证

V2.0.12 将本地串口扫描、远程发现定时器、AI 缓存目录填充及工作空间目录查询放在表单首帧之后。窗口创建、紧凑布局、当前值及安全的初始按钮状态仍在主线程完成。不要把 HWND 可见当作完整绘制，也不要在线程中调用 Win32 控件接口。

Windows 构建使用 `tests/performance/ConnectionDialogBench.cpp` 和 `MeasureConnectionDialogs.ps1`，从真实鼠标点击分别记录创建、可见、标题、首帧 GDI 绘制完成和消息响应的时刻。首帧标记仅在 `SERIALCTL_UI_METRICS` 启用时发布，不代表显示器/DWM 呈现时刻。

- 基线：已发布的 V2.0.11，固定完整 ZIP SHA-256。基线没有首帧标记，只比较其共同的可见/响应指标。
- 候选：同次构建的已验证完整 ZIP。SSH、串口、Telnet、远程串口、AI 和设置在深浅主题各五次；候选必须观察到首帧标记。
- 持续输出：在同一桌面通过默认端口 23 的真实 Telnet 连接接收受控 loopback 流量，再对基线/候选分别测量六种弹窗各两次。记录已发送字节数与终端绘制计数；该流量不是物理 UART 或真实 SSH 性能。
- `ui_dialog_viewport` 检查隐藏窗口和离屏打印不会启动查询、首帧只投递一次任务、关闭前未绘制时不遗留任务，以及字体更新不会暴露尚未展开的列表、首次展开保持统一样式。
- `ai_device` 检查枚举不早于串口表单显示，等待时 Cancel 可用、连接禁用，保留 115200/8N1 及 28px 字段。
- `ai_pane` 检查 500 个缓存目录在首帧后填充、不覆盖提前输入的路径、不自动建立连接；保留工作空间浏览及多 DPI 检查。

最终页面几何与像素、原生鼠标拖动、升级提示与签名升级仍经过原有门槛。真实低配置电脑、Win7 SP1、现场驱动和服务器未运行时不得宣称通过；长对话排版由独立 AI 回归覆盖，不等于该桌面计时包含真实模型长对话。

## 原生列表兼容边界

Windows 定向诊断 `40997481440` / `40997695452` 对相同鼠标、键盘及重入选择用例比较了延迟全部列表初始化、提前行高、提前挂接、提前挂接加行高和保留原生初始化等方案。前四种在部分 96/144 DPI 场景中使列表首项点击仍停留在末项（top index 1，selected 2），随后方向键没有触发应有的选择通知；保留原生初始化通过深浅主题、96/144/192 renderer scaling、owner-drawn/普通列表所有检查。

最终实现保留 `UiStyleField` 中原生列表几何和裁剪的初始化时序。优化隐藏绘制、重复字体准备及后台查询的启动位置，不以延迟必要几何换取错误的首次选择。上述 renderer scaling 不是 Windows 系统 DPI 实机验收。

持续输出连接的准备位于计时区间外，通过原生字段和连接命令建立受控 loopback 会话，避免基线弹窗首次激活尚未结束时抢先点击连接。真正记录的六种入口仍使用桌面鼠标；准备失败打印端口、窗口/字节状态和内联错误，不生成可用的计时样本。

隔离 Windows 桌面的默认端口流量准备已在 `41010832839` 单独验证；该补充场景不将跨进程自动修改自定义端口作为验收目标。标准端口必须成功绑定并收到实际数据，否则计时失败，不伪造持续输出。
