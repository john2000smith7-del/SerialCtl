# V1.0.6 Windows 7 SP1 与硬件验收

当前真实 Win7、UART、IT6332A 和8小时现场状态：**未运行**。Windows Server 2022 CI、PE 6.01和受控后端均不能替代现场结果。最低平台为Win7 SP1 x64；不安装.NET或额外VC Runtime，保留现有YY-Thunks/固定PuTTY。

## 准备与记录

完整解压发布ZIP，根目录serialctl.exe/plink.exe/psftp.exe保持同目录。记录完整源码SHA（MANIFEST.json）、ZIP SHA256、系统补丁、CPU/RAM、DPI、串口转换器与驱动、LAN链路、UART速率、客户数量、IT6332A固件/USB或RS232。USB电源需既有NI-VISA18完整离线驱动；没有设备则填写未运行。

## 执行

1. Win7 SP1干净环境双击运行，检查无缺失DLL/入口点、默认浅色及深色。按MANUAL-REGRESSION.md逐项DPI、动态拖动、编辑焦点、CMD、终端与全部断开。
2. 用第二串口/设备替身硬件回环分别打开COM3和COM5，明确实际波特率与8N1/流控。用随包Python `serialctl_client.py <IP> list` / `watch COM3` / `send COM3 ...`；另一个AI与另一SerialCtl远程COM3同时接收写入，COM5数据不得串流。关闭COM3，COM5继续；不存在/未打开/占用COM失败原因可见。
3. 使用随包serialctl_ws.Client原始`input(resource, bytes(range(256))*N)`，在对端及启用RX/TX Base64 trace的日志分别核对字节和SHA256。覆盖NUL/FF/CRLF、UTF8/GBK跨包，启动输出、握手后立即输出；网络Ping/Close/旧Telnet握手不得进入UART。不可过滤合法FF。复现线路framing/parity/overrun错误并核对ClearCommError诊断；照片异常根因仍需原始字节证据。
4. 占用7000后验证自动回退；占满7000–7015，本地UART/CMD仍能用。开两程序实例后自动发现报告歧义，指定端口/instance正确选；停止/重启服务后旧instance不能执行输入。
5. 逐级1/2/8/32客户端和多COM持续负载，另设停止读取客户端；健康端、本机日志和终端继续。记录输入批次和RX/TX校验，无任务级互斥承诺。频繁连接关闭、目标消失、网络中断、设备拔插、取消/退出，检查无崩溃挂起/线程句柄增长。
6. 有线LAN测Publish入口→客户端完整收到（需同步/回环方法明确起止），另测PostData→绘制及物理屏幕（后两者分开）。报告P50/P95/P99、样本、速率、串口数、客户端数和负载。10ms转发/50ms显示是优化目标，不是未测承诺，不包含UART线速时间。
7. IT6332A真实USB/RS232连接，勾选1/3而不选2：GUI与网络总加/掉电只动1/3，2保持。网络电压/电流/模式/通道替换/保护/预设/复位/SCPI/任务均前置拒绝；action查询区分排队/完成/失败，相同requestId不重复执行。断线/超时只查询状态，不自动重发。
8. 本地串并联/跟踪、保护、预设和自动化保持；任务停止/正常退出关闭该任务控制通道，不影响未选通道。拔线时不得显示已成功掉电；恢复后由人核对真实输出。用户无电源实机时这些均未运行。
9. 至少8小时真实持续输出：每分钟记录累计RX/TX字节/校验、CPU、工作集、线程、句柄、错误；每小时采尾延迟，穿插慢客户端、网络/设备中断、日志增长与磁盘满/只读。停止/退出检查剩余进程与设备释放。短时CI结果单独标记，不能替代8小时。
10. SSH/Telnet/SFTP真实服务器、中文/空格文件名、覆盖确认/取消、任务取消/路径跟随和PuTTY指纹回归；动态SFTP列宽检查。

每条填写：环境、步骤、通过/失败/未运行、原始证据路径、限制、复核人。异常记录原始字节/诊断，不根据照片推断根因。
