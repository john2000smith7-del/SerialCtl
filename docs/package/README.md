# SerialCtl V2.0.10

Win7 SP1 x64 原生便携程序。解压后 serialctl.exe、固定 plink.exe 与 psftp.exe 保持同目录；Windows 主程序不需要 Python、.NET 或另外安装 VC Runtime。NI-VISA 18 完整离线驱动保持 drivers 目录，仅电源 USB 访问需要相应驱动。

AI 页提供鲸鱼娘宠物，打开后约 4 秒自动播放三次前后跳步和拳击；点击挥手，右键或顶栏小爪按钮打开动作、大小和设置。默认在桌面悬浮，可全局拖动，主窗口最小化后仍显示；右键可返回窗口内、切换置顶或打开主窗口。可关闭开场播放，位置和偏好会保存。

继续开放 USB/VISA 与 RS232 电源连接。电源页可选择已经打开的实时终端并拖动两栏比例，默认等分。AI 不主动公开姓名，用户询问时回答 jiojio；自动介绍不执行命令。自动恢复需在电源页绑定当前板卡终端和勾选通道后开启。断电读回后至少等待 10 秒才上电，停止/断线取消待上电。

V2.0.5 修复 AI 完成回答后的过程自动折叠，并移除远程串口 UDP 识别和连接入口；仅保留 SerialCtl 自身服务发现。继续使用找回的原更新签名身份；原信任链 V2.0.2／V2.0.4-r1 可直接自动升级，保留 update.ini、配置和数据。

软件启动自动提供单一 WebSocket v1 服务（TCP 7000–7015）。同一 Windows 用户会话只运行一个 SerialCtl 主窗口，再次打开会唤回已有窗口。用户先在 GUI 打开 COM 或 CMD。远程串口填写 IP、明确 COM，通过相同服务发现和连接；发现多个服务时可指定端口。不猜测第一个串口，不再支持 telnet/IP:7000 串口透传或旧 HTTP REST。

Linux Python 3 标准库客户端：serialctl_client.py、serialctl_api.py 是同一个 serialctl_ws.py 核心的入口，必须放在同一目录。

```sh
python3 serialctl_client.py 192.168.6.86 list
python3 serialctl_client.py 192.168.6.86 send COM8 'uname -a' --ending CRLF
python3 serialctl_client.py 192.168.6.86 watch COM8
python3 serialctl_api.py 192.168.6.86 power
python3 serialctl_api.py 192.168.6.86 on
python3 serialctl_api.py 192.168.6.86 off
```

只有 IP 和 COM 即可发现并选择；歧义时用 `--port 7001` 或 `--instance <返回值>` 明确实例。发送返回 queued，不能等同于命令执行成功；持续 watch 无轮询。电源操作只作用于本机当前勾选通道，无远程参数、SCPI 或任务接口。更多示例见 AI-SERIAL.md 和 AI-API.md。

CMD 支持本地左右移动、Backspace/Delete/Home/End、历史、中文、复制粘贴和多行提交。网络必须发送完整行，按 session.get 查询的代码页编码。隐藏 Win7 控制台输入桥接支持多字节字符，stdout 保留原始管道；本轮不支持 Ctrl+C 和全屏交互，全部断开会关闭 CMD 进程树。后台输出不强制回到底部，主动键入/执行命令回到实时位置。

终端拖选完成后自动复制，双击选词同样复制；右键直接粘贴一次，不额外追加回车。剪贴板含换行时，CMD 会提交完整行并保留末尾未换行的草稿。原有复制粘贴快捷键继续可用。顶部“设置”包含回显、时间戳、编码、换行方式、日志、诊断和终端操作，按全局与当前会话区分。

连接页底部“全部断开”取消连接建立、SFTP/命令任务并释放本地设备；电源断开在后台处理，任务拥有的通道尝试掉电并确认，断线时输出状态不能保证。顶部“设置”可保存网络连接诊断 JSON，或启用 RX/TX Base64 字节核对；未启用时保留常规文本日志。真实空行有时间戳，屏幕填充没有。

本包的 Win7 与真实串口/IT6332A 验收状态必须查看相应交付记录；Windows 2022 CI 不代替现场。8 小时现场运行、Win7 焦点和实际电源均需人工验收。

## AI 智能串口助手

点击顶部 AI，填写 Linux Codex 服务器的 SSH 地址、端口、用户名和密码，测试后进入对话。Windows 不需要安装 Codex；模型和网关认证沿用服务器配置。密码默认不保存，选择记住时由 Windows 安全凭据存储；首次连接须核对 SSH 主机指纹。

对话输入栏位于原终端区域内部底部，使用服务器默认模型，发送和停止为独立操作；消息支持上下滚动和历史恢复。串口由用户明确选择，不默认本地 COM；选择“连接远程串口…”后填写来源 IP，查询其已经开放的串口并连接。AI 可读取真实日志、观察新输出，可直接在明确关联的串口输入命令，无需逐条二次确认，提交不代表设备执行成功。不增加跨客户端写入仲裁。使用步骤与原 Linux 客户端说明见 AI-SERIAL.md。

尚未完成真实 SSH/网关/实体串口及 Windows 7/10/11 现场验收，不能据自动测试宣称已完成这些验收。

## 内网自动更新

编辑程序旁 `update.ini` 的 `[update]` / `url=`，填入服务器完整 `update.json` 地址；V2.0.2 已默认填写 http://172.16.3.188/external/serial/update.json；旧安装若保留了空白或其他地址，需手动修改一次。V2.0.0 起服务器只放完整 ZIP 和内嵌签名 update.json 两个文件。每次启动后台检查，发现更高版本并验证签名后下载完整 ZIP，在没有会话、连接建立或任务时更新并重启。服务器不可达、下载失败或校验失败不妨碍当前版本运行。更新保留 `update.ini`、用户命令、日志和 NI-VISA 驱动。详细操作、日志和恢复办法见 `AUTO-UPDATE.md`。

V1.10.0 及以前首次切换双文件格式需手动部署 V2.0.0；后续版本可按签名清单自动更新。更新功能没有修复本次独立审核登记的全部历史问题。

## V2.0.2 AI 终端与电源

AI 输入栏选择已连接的串口、远程串口、CMD、Telnet 或 SSH，读取真实输出并直接发送匹配系统的单行命令。电源页先连接 IT6332A 并勾选通道，再在 AI 中明确要求上电/下电；无需终端选择或二次确认，不改变电压/电流/模式，结果依据 action 逐通道回读。升级后点击“新建会话”加载新增工具，旧历史仍可恢复。

AI 页面可展开右侧实时终端并拖动调宽，仅使用服务器默认模型。AI 连接设置可填 Linux 项目绝对目录；服务器原生工具可按 SSH 用户权限修改代码和运行命令，对话显示实际输出与 diff。目录须在 Codex 容器可访问范围；升级后新建 AI 会话。同版本 V2.0.2 不触发自动更新，退出后手动替换一次，保留配置和数据。

V2.0.3：AI 与实时终端默认等分、可调整比例；长行横向查看；消息选中文字即复制。连接栏共用顶部原图标，尺寸20逻辑像素；命令卡片仅留一个小圆拖动标记。设置底部显示版本与 Application design by jiojio。检测到可信新版后必须点确定才开始下载，关闭提示退出；原 V2.0.2 升至本版仍按旧版更新行为完成。
