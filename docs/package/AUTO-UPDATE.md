# 内网自动更新

## 配置一次，以后只改网址

先完整解压 V1.0.7 或以后带更新器的正式包，确保 `serialctl.exe`、`plink.exe` 和 `psftp.exe` 位于同一目录。旧版本没有更新器，第一次升级需要手动解压。

用记事本打开程序旁的 `update.ini`：

```ini
[update]
url=
```

在 `url=` 后填写管理员提供的**完整 `update.json` 地址**。已知服务器是 `172.16.2.188`，但网页发布目录尚未确定；本包保持留空，不假定路径。例如管理员最终确认目录为 `/SerialCtl/` 时才填写 `http://172.16.2.188/SerialCtl/update.json`。不要填只有 IP 的网页首页或下载 ZIP 的地址。

保存文件并重启程序生效。以后服务器 IP、端口或目录改变，只需再修改这个文件。留空可停用更新检查。自动更新保留这个文件，不覆盖您设置的网址。建议将便携程序放在当前用户可写的目录；如果目录只读，先由管理员正常部署到可写位置，程序不会自动请求管理员权限。

## 程序行为

每次启动后台检查一次，界面可以正常使用。服务器不可达、下载中断、版本未提高、签名或文件校验失败时，继续使用当前版本；不会因为无法更新而阻止启动。

发现更高版本后，下载到本机临时更新目录并校验；只有没有会话、连接建立、命令或 SFTP 任务、电源活动等占用时才自动退出并替换重启。如果检查/下载期间已经操作程序、打开电源页面或开始编辑/拖动，本次运行只提示发现新版；请结束工作后在空闲时重新启动，程序会重新检查，不会在稍后突然重启。同一安装目录另有程序、CMD 桥接或 PuTTY 实例仍运行时，本次拒绝安装；关闭这些实例后，在空闲时重新启动检查。

更新只覆盖批准的程序和随包说明，不覆盖 `update.ini`、用户配置、保存命令、日志或 `drivers`。NI-VISA 驱动不会在每次更新时重复下载或安装。更新程序先备份旧文件，文件替换失败会尝试恢复；不能把突然断电等未经过现场验证的情况解释为一定自动恢复。

HTTP 更新也必须通过程序内置公钥的签名验证；只有管理员持有的离线私钥才能签发。不要在客户端关闭验证，不要从网页下载一个新公钥替换程序的信任密钥。服务器托管的哈希不能单独代替数字签名。

## 部署与恢复

服务器管理员需使用源码仓库的 `tools/new_update_feed.py`，从已验证的正式包生成 `update.json`、`update.json.sig` 和 `files` 目录；细节见源码的 `docs/architecture/AUTO-UPDATE.md`。Python/OpenSSL 只在管理员制作更新时使用，运行 SerialCtl 的电脑和静态网页服务器不需要安装它们。签名私钥不得放进 Git、更新网站或客户端包。

遇到更新错误，先保留当前可用版本。核对 `update.ini` 完整网址、服务器文件是否齐全，以及程序目录是否可写。若文件替换被安全软件或其他程序占用，关闭占用后重新启动检查。若中断后仍无法启动，从可信渠道重新解压完整正式包到新目录，复制原 `update.ini` 后运行；用户数据通常保存在 `%LOCALAPPDATA%\SerialCtl`，不要删除该目录。保留更新目录、原始错误信息与日志供管理员分析。安装日志在程序目录 `.serialctl-update/<本次随机标识>/update.log`，工作进程启动失败时尽可能另存 `.serialctl-update/last-install-error.log`；备份在同一子目录的 `backup` 中；失败恢复使用 `.serialctl-update/transaction.txt`，不要在更新中删除或改写这些文件。检查/下载失败在窗口状态区显示，尚未安装时不一定存在安装日志。

安装或新版启动失败后，`.serialctl-update/failed-version.txt` 会阻止同一版本反复失败重启。优先请管理员发布更高版本；只有核实问题已解决并保留日志后，管理员才可在所有实例退出时移走该标记，再启动重试。不要因看见失败标记就删除备份或恢复记录。

当前服务器真实路径、网页权限、Win7 实机和断电恢复需现场验收。HTTP 服务器应只提供已签名的静态发布文件，不需要上传或远程执行权限。
