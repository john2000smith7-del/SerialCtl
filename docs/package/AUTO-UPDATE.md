# 内网自动更新

## V2.0.0 起只部署两个文件

每次版本交付会同时提供：

```text
update.json
SerialCtl-V2.0.3-Win7-x64.zip
```

`update.json` 内含版本、完整 ZIP 的文件名、大小、SHA-256、运行文件清单及数字签名。使用随版本配套提供的文件，不要手动修改 JSON、重新压缩 ZIP 或把普通 SHA-256 文本当作签名。服务器无需 Python、解压工具或额外服务，也不需要 `update.json.sig` / `files` 目录。先上传完整 ZIP，完成后替换 `update.json`；保持二者在同一静态目录。

## 客户端配置不变

V1.10.0 及更旧客户端不支持这个双文件格式，第一次切换到 V2.0.0 需要手动解压部署一次。保留原 `update.ini`，保持 `serialctl.exe`、`plink.exe`、`psftp.exe` 同目录。

打开程序旁的 `update.ini`：

```ini
[update]
url=http://172.16.3.188/external/serial/update.json
```

V2.0.2 已按用户确认预填上述地址。ZIP 和 update.json 同放在服务器的 `/external/serial/` 网站目录，不解压 ZIP，不改文件名。自动更新会保留已有 INI，旧安装若仍是空白或其他网址，需要手动改成上述地址一次；已正确填写则无需修改。不要填 ZIP 地址或网页首页。留空停用检查，保存后下次启动生效。

## 启动自动更新

每次启动在后台检查一次。验签后，版本较新才自动下载完整 ZIP，校验大小和 SHA-256 后只提取允许更新的运行文件。下载直接写临时文件；解压后逐一校验运行文件，删除临时 ZIP，再交给安装器验证和替换。

程序只在原有空闲条件满足时自动安装并重启，不要求点击更新按钮。串口、SSH/CMD、SFTP、电源或其他任务正在使用时不会为更新强行断开；检查/下载期间开始操作时，本次只提示新版，结束工作后在空闲时重新启动。更新源不可达、格式不符、签名错误、损坏或截断、版本未提高时继续使用当前程序，不会阻止启动或自动重发设备命令。

完整发布包包含 NI-VISA 驱动，所以每次在线更新会下载整个 ZIP。安装只覆盖签名清单中批准的运行文件，不覆盖 `update.ini`、用户配置、命令、日志或 `drivers`，不重复安装驱动。程序目录需可写，同目录其他 SerialCtl/CMD/PuTTY 实例需退出。

## 发布和恢复

签名由发布方完成。管理员只接收并上传配套两个文件，不需要生成签名或运行 Python。客户端以内置 RSA 公钥验证签名；不能用关闭验签或下载替换公钥解决错误。正式签名私钥不得随包、上传网站或提交 Git。

安装先备份，再替换并等待新程序确认启动。替换或启动失败时尝试恢复，并记录失败版本，避免循环更新。这不代表已经验证任意断电、磁盘故障或安全软件干预场景。

日志和备份位于程序目录 `.serialctl-update/<本次标识>/`，安装日志是 `update.log`，备份在 `backup`；持久恢复记录为 `.serialctl-update/transaction.txt`。启动安装器失败时尽可能记录 `.serialctl-update/last-install-error.log`。不要在更新过程中删除这些文件。失败版本标记 `.serialctl-update/failed-version.txt` 应保留供管理员排查，优先发布更高版本解决；仅确认问题解决后，在所有实例退出时移走标记重试。

遇到无法启动，可从可信渠道将完整正式包解压到新目录，保留原 `update.ini`。用户数据通常保存在 `%LOCALAPPDATA%\SerialCtl`，不要删除该目录。真实 Win7、内网服务器、实体设备、长时间运行和断电恢复仍需现场验收。

## V2.0.3 确认后下载

启动先读取清单并验签、比较版本；可信更高版本通过检查后显示强制提示，仅“确定”。点击确定前不请求压缩包、不创建下载暂存目录；关闭提示退出程序。确认后显示真实字节下载进度与校验阶段，完成后沿用安全空闲安装／重启。下载或安装失败时重试或退出，不能绕过已要求的更新继续操作旧版。网络不可用或清单不可信时不能伪称发现新版，沿用离线可用行为；已经运行的设备任务不突然中断，空闲重启确认升级。

服务器依旧只上传版本ZIP和其内嵌签名update.json，update.ini不变。已安装V2.0.2首次升级到V2.0.3使用旧客户端原有行为；升级完成才采用新增提示。
