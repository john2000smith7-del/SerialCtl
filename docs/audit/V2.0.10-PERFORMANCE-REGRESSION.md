# V2.0.10 性能与串口实时性回归

状态：Linux 模型层配对数据及 a903bb5 的 Windows 受控绘制专项已执行；最新功能快照尚需匹配运行。没有声称物理串口或屏幕达到 0ms。

## 已执行：20,000 行预览

原始数据和可重跑驱动位于 ../testing/results/V2.0.10-arch-final/native-model/。基线 9d70d93，候选 4927eb0；同一 AMD EPYC 9V45 云主机、Linux 6.18.55、GCC 14.2.0、-std=c++17 -O2。Linux wchar_t=4，不能当作 Windows wchar_t=2 的绝对性能结果。

每种负载各 30 次：80×24 网格；每历史输入行 60 个字符及 CRLF；先建立关闭折行的历史投影，再计时 PreviewInput。完整文本校验在计时之外。RSS 来自 /proc/self/statm，在预览存活时采样，受分配器和进程状态影响。

| 历史输入行 | 原中位数 ms | 新中位数 ms | 原 P95 ms | 新 P95 ms |
|---|---:|---:|---:|---:|
| 0 | 0.004 | 0.003 | 0.005 | 0.005 |
| 2,000 | 0.495 | 0.019 | 0.560 | 0.046 |
| 20,000 | 8.973 | 0.625 | 10.259 | 0.810 |

20,000 行场景中，预览存活时相对预览前 RSS 的观测增量为原 68,591,616 字节、新 8,916,992 字节。它不是精确分配量或 Windows 峰值工作集。该配对运行表明不可变历史共享减少复制，不能推导所有设备/负载的固定倍数改善。未变化的草稿另由 viewport 修订号缓存复用。

## Windows 串口显示专项

AiDeviceTest 使用真正的生产窗口处理器和终端绘制器，向受控串口会话交接 16 个标记。测试期间故意持有真实 ApiServer 发布互斥量，断言终端在网络发布恢复前已绘制该标记；QPC 记录 callback→PaintTerminal 完成微秒数。另验证其他会话积压不埋住活动串口回显，1MiB 持续字节由正常绘制机会继续处理，不依赖可见窗口接收刷新定时器。

[a903bb5 原生回归 40701860254](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40701860254) 的 16 个样本中位数为 0.974ms，最小 0.671ms、最大 1.808ms；这是一次受控运行而非统计性现场 SLA。输出 serial-realtime-display.json，保存在该运行的原生诊断制品。此测量不包含 UART 线速、USB 转串口驱动接收、DWM/显示器扫描，也不证明真实输入→设备执行→回显为零延迟。

## 现场实时性测量步骤

1. 记录 CPU/内存、Windows 版本/DPI、串口芯片/驱动、波特率、流控、网关客户端数量和是否有其他会话持续输出。
2. 使用同一硬件和完整解压包；分别测本地与远程，静态提示符及持续输出两个负载。每场景至少 1,000 次，保留原始标记/序号及 RX/TX 日志。
3. 分开测设备发送→本机接收、接收回调→PaintTerminal、实际屏幕呈现；外部时钟或逻辑分析仪用于物理段，不能把软件回调时间当成 UART 或显示扫描时间。
4. 保留 P50/P95/P99/最大值、吞吐、CPU、工作集和丢失/重排计数；连续运行至少 8 小时，检查流控、设备拔插和远程慢客户端不拖住本地交互。
5. 不自动重发因超时而执行状态未知的设备指令。当前 UI 和协议保持原操作方式。
