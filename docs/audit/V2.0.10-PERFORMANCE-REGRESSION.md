# V2.0.10 性能与串口实时性回归

本文的 Windows 配对结果对应源码 `23277a862cee1be79138847b35c8f422e53e8125`，包含 `e7218ab` 的终端延后重排修复。软件路径、受控传输和实际 Win32 绘制已测；物理 UART、USB 驱动、远端设备与屏幕扫描未测，不宣称绝对 0ms。

## 同机 Windows 前后对照

[运行 40791932764](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40791932764) 对接受基线 `9d70d93` 与候选 `23277a8` 使用同一套驱动，交错执行各 3 个独立进程。机器为 AMD EPYC 7763、2 核 4 逻辑处理器、约 16 GiB 内存，Windows Server 2022 20348、Visual Studio 2022、Release x64。表中每格为三次进程内指标的中位数，不是合并所有样本后的分位数，也不是统计置信区间。云主机调度和绘制提交时间会波动。

[原始制品](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40791932764/artifacts/12861694494)包含逐进程日志、全部样本和环境记录；仓库保存了原样抄录的 [comparison.json](../testing/results/V2.0.10-arch-final/windows-23277a8/comparison.json)及[来源说明](../testing/results/V2.0.10-arch-final/windows-23277a8/README.md)。驱动在 [tests/performance](../../tests/performance/)；它们只注入临时性能工作树，不加入发布程序。

20,000 行预览：80×24 模型，每行 60 字符及 CRLF，先构建关闭折行的历史投影，每个进程计时 30 次预览创建。完整文本检查和工作集采样在计时外进行。工作集是 Windows 观测值，受分配器和进程状态影响，不是精确分配量。

| 指标 | 基线 | 候选 |
|---|---:|---:|
| 预览 P50 / P95 | 27.892 / 32.841 ms | 1.951 / 3.024 ms |
| 预览存活时观测工作集增量 | 56,545,280 B | 3,489,792 B |
| 预览进程峰值工作集（含文本校验） | 125,284,352 B | 71,757,824 B |
| 主窗口绘制 P50 / P95 | 2.195 / 2.976 ms | 1.124 / 1.771 ms |
| 终端绘制 P50 / P95 | 1.700 / 2.540 ms | 1.302 / 1.950 ms |
| 首轮程序化缩放 P50 / P95 | 33.710 / 37.018 ms | 35.226 / 37.499 ms |
| 稳定期程序化缩放 P50 / P95 | 34.066 / 37.296 ms | 34.074 / 37.123 ms |
| 交互尺寸循环 P50 / P95 | 30.264 / 32.854 ms | 30.235 / 33.021 ms |
| 结束尺寸循环时的单次重排 | 3.135 ms | 3.492 ms |
| 受控键入及回显绘制 P50 / P95 | 2.234 / 2.990 ms | 1.857 / 2.498 ms |
| 受控键入吞吐 / CPU 时间 | 448 B/s / 2250 ms | 549 B/s / 1828.125 ms |

绘制场景使用可见窗口和生产处理函数，活动会话位于真实主窗口会话列表，终端预置 1,000 行。每个进程先预热，再采集 200 个主窗口和 200 个终端绘制样本。程序化缩放交替两个实际尺寸，首轮 40 次、稳定期 80 次，并检查实际窗口尺寸及 `WM_SIZE` 到达。交互尺寸循环另采 80 次，在生产 `WM_ENTERSIZEMOVE` 与 `WM_EXITSIZEMOVE` 之间调整窗口；断言中途不重排、结束后提交最终网格。这里的尺寸循环是程序驱动的，真实鼠标拖动另由桌面审计覆盖。结束时的单次重排每个进程只有一次，不能作统计性结论。

输入场景通过终端的 1,000 个 `WM_CHAR` 消息、受控本地串口传输和逐次本地回显绘制，验证发送字节总数。计时包括处理与 GDI 提交，另记录进程 CPU；之后再执行 1,000 次输入观察资源。此吞吐刻意包含每个字符后的绘制，不代表串口线速或物理键盘响应。

此次配对中预览、绘制和受控输入改善明显，缩放指标接近且部分候选数值略高。稳定缩放未复现早期的明显 P95 差异，但三次运行不足以证明所有硬件和负载均无退化。原生 `terminal_preview` 还把完整文本验证计入耗时，与上表只计时预览创建的方法不同，不能直接比较其绝对值。

## GDI 与资源趋势

| 检查点（每版各三进程的中位数） | 基线 | 候选 |
|---|---:|---:|
| 进程开始 | 3 | 3 |
| 绘制预热后 / 200 次绘制后 | 75 / 75 | 79 / 79 |
| 三轮缩放后 | 87 / 87 / 87 | 91 / 91 / 91 |
| 两轮各 1,000 次输入后 | 87 / 87 | 91 / 91 |
| 测试窗口和主窗口对象销毁后 | 72 | 72 |

候选持久缓冲在预热后多 4 个 GDI 对象。两组在首次尺寸变化后的中位数均增加 12 个，后续重复尺寸及输入检查点的中位数没有继续增长。剩余对象包含[圆角表面缓存](../../src/app/UiRoundedSurface.h)等进程级资源；其普通缓存受 96 项、16 MiB 预算约束，单个较大表面另受尺寸上限约束。总数不能独立证明每个对象的归因，也不等于 8 小时或任意尺寸序列的无泄漏证明。

## WebSocket 小帧

使用本机回环；每个客户端接收并逐字节校验 1,000 个 64 字节包，从 `Publish` 入口计时到客户端完成解码。两组网络测试源相同，仅调整测试端口避免连续进程的 `TIME_WAIT`。吞吐按客户端接收的已校验总字节计算，MB 为十进制，不是物理串口或 WAN 吞吐。

| 客户端 | P50 ms（基线→候选） | P95 ms（基线→候选） | MB/s（基线→候选） | 活跃/回收后句柄（基线；候选） |
|---|---:|---:|---:|---|
| 1 | 0.0624 → 0.0562 | 0.0772 → 0.0699 | 0.957 → 1.070 | 129 / 110；128 / 107 |
| 2 | 0.0759 → 0.0670 | 0.0961 → 0.0901 | 1.480 → 1.652 | 140 / 110；139 / 106 |
| 8 | 0.1309 → 0.1128 | 0.1749 → 0.1458 | 2.948 → 3.535 | 206 / 110；210 / 106 |
| 32 | 0.3676 → 0.2849 | 0.5725 → 0.4131 | 3.665 → 4.804 | 470 / 110；498 / 106 |

32 客户端进程 CPU 时间为 1312.5→1015.62ms；8 客户端均为 296.875ms。候选在 32 客户端下的活跃句柄更多，停止后的句柄回落；不能宣称所有资源指标都减少。每进程另有慢订阅者隔离及 9,830,400 字节完整性验证。

## 串口收显专项

`AiDeviceTest` 使用生产窗口处理器和终端绘制器，交接受控串口字节。故意持有真实 `ApiServer` 发布锁，断言网络发布恢复前终端已经绘制标记。QPC 记录回调到绘制完成时间；另验证活动会话优先、后台进度及 1 MiB 积压通过正常绘制机会继续处理，不依赖可见窗口的 10ms 接收定时器。

[原生专项 40791936678](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40791936678)的 16 个样本中位数为 1.005ms，范围 0.587–1.365ms；同源码的[完整构建](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40791932726)对应中位数为 0.986ms，范围 0.676–1.393ms。原始 [serial-realtime-display.json](../testing/results/V2.0.10-arch-final/windows-23277a8/serial-realtime-display.json)及[诊断制品](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40791936678/artifacts/12862761665)保留。两次都是受控运行，不是现场 SLA；不含 UART、USB 驱动、DWM 或显示器扫描，不证明设备往返为零延迟。

## 早期结果和纠正记录

- [40788006100](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40788006100) 的固定尺寸缩放断言失败，旧的缩放耗时作废；后续按真实桌面工作区选尺寸，并保留尺寸和消息断言。
- [40789670203](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40789670203/artifacts/12861441191)及[40790636170](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40790636170/artifacts/12861039139)中出现候选缩放 P95 偏高。旧驱动的活动会话不在主窗口会话列表，未覆盖实际终端重排；后续修正该测试范围，并发现、恢复了拆分时遗漏的拖动/动画延后重排保护。本文主表采用修正后的 `23277a8` 数据，保留旧数据供追溯。
- [7c401bf 配对数据](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40788889475/artifacts/12861495100)等较早运行使用过不同云主机 CPU，不能跨机器混合绝对值或选择性拼接最优结果。

Linux 模型配对数据和驱动保留于 [native-model](../testing/results/V2.0.10-arch-final/native-model/)。接受基线 `9d70d93` 与候选 `4927eb0` 在同一 AMD EPYC 9V45、Linux 6.18.55、GCC 14.2.0、`-O2` 下各测 30 次：

| 历史输入行 | 原 P50 ms | 新 P50 ms | 原 P95 ms | 新 P95 ms |
|---|---:|---:|---:|---:|
| 0 | 0.004 | 0.003 | 0.005 | 0.005 |
| 2,000 | 0.495 | 0.019 | 0.560 | 0.046 |
| 20,000 | 8.973 | 0.625 | 10.259 | 0.810 |

20,000 行预览存活时观测 RSS 增量为 68,591,616→8,916,992 字节。Linux `wchar_t=4`，Windows 为 2，不能把 Linux 结果视为 Windows 绝对性能或精确分配量。

## 验收矩阵和现场步骤

| 场景 | 已执行 | 尚未完成 |
|---|---|---|
| 大历史及高频输入 | Windows/Linux 配对、文本完整性、工作集、受控输入 CPU/吞吐与绘制 | 真实设备和物理回显分布 |
| 绘制与连续缩放 | 200 次窗口/终端绘制，120 次程序化及 80 次交互尺寸循环，GDI 分段采样；像素等价 | 长时间、任意尺寸和真实高 DPI |
| WebSocket 小帧 | 1/2/8/32 客户端延迟、吞吐、CPU、线程/句柄及完整性 | WAN 与事件创建次数的实测对照 |
| 128 慢客户端 | 协议半帧期限、槽位回收和健康查询恢复，`23277a8` 回归通过 | 外网及长时间资源趋势 |
| SSH 反复连接/断开 | 16 次受控循环最大 110ms；预热后句柄 122→122、线程 4→4，见 [原始数据](../testing/results/V2.0.10-arch-final/windows-23277a8/ssh-lifecycle.json) | 真实 SSH 服务、网络和 Win7 |
| SFTP 取消 | 16 次控制器循环句柄 107→107；长路径、持续输出取消与清理预算，见 [原始数据](../testing/results/V2.0.10-arch-final/windows-23277a8/sftp-controller.json) | 真实服务器大量任务、断线和残留文件 |
| 日志 | 65 MiB 轮转、慢复制与并发停止、注入磁盘满、真实只读句柄写失败、等待者退出 | 物理磁盘满、实际卡住的 SMB、8 小时现场 |
| UI 设置持久化 | 阻塞存储时提交不等待、最新快照合并、关闭刷新、真实 INI 兼容 | 现场磁盘性能及异常断电 |

现场步骤：

1. 记录 CPU/内存、Windows/DPI、串口芯片和驱动、波特率、流控、网关客户端数量以及其他会话负载。
2. 同一设备使用完整解压包，分别测试本地/远程、静态提示符/持续输出；每场景至少 1,000 次，保存原始序号和 RX/TX 日志。
3. 分别测设备发送到接收、接收回调到绘制、实际屏幕呈现。物理段使用外部时钟或逻辑分析仪，不能以软件回调时间代替。
4. 记录 P50/P95/P99/最大值、吞吐、CPU、工作集和丢失/重排，连续至少 8 小时，覆盖流控、热插拔、慢客户端、SSH/SFTP 断线及 IT6332A 实机。
5. 对执行状态未知的设备指令不自动重发。真实 Win7/Win10/Win11、120/144 DPI 和硬件测试均应单独记录，不能由 CI 仿真替代。
