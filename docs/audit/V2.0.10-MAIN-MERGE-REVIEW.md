# V2.0.10 合并评判与交付边界

## 结论与授权

用户于 2026-10-29 明确要求：不将主机/硬件实测作为本次合并门槛；复核升级兼容性后，将通过检查的分支合并到 main，交付最终编译版本，电源功能保持禁用。此前禁止合并 main 的任务约束由这次授权覆盖。真实串口、远端设备、Win7 实机及长时间测试仍标记为未执行。

在现有架构整改和回归证据基础上，修正下述电源开关并通过匹配最终源码的 Windows 检查后，代码满足本次合并条件。合并前复核 PR 无冲突、无未处理的阻断性审查以及成功的构建检查；合并后从 main 的合并提交重新执行完整构建与桌面交互审计，交付该 main 构建的制品。精确提交、运行编号、下载地址和摘要记录在 [PR #32](https://github.com/john2000smith7-del/SerialCtl/pull/32)，避免在制品来源确定前预先声称通过。

## 电源功能

复核发现候选源码及原 main 的 `PowerService::ConnectionAvailable()` 均为 true，与用户本次要求不一致。现设为 false；生产 `Submit` 在参数验证、排队和创建动作编号前拒绝所有电源操作，USB/VISA 枚举与 VISA 探测直接返回不可用。GUI 复用已有未开放提示，不展示设备、刷新或驱动操作；AI 只能读到未连接状态，合法远程 ON/OFF 请求也被拒绝，不改变状态。电源页布局保留。

`power_connection_gate` 不带测试宏，验证真实 USB/串口、仿真、未知后端和全部操作均不排队、不改变设备状态；`ai_device_bridge` 验证 AI 无法提交电源操作。完整包 GUI 冒烟验证未开放提示及设备字段不存在，并通过实际 WebSocket 请求验证合法 ON/OFF 被拒绝。`power_service`、`ai_device` 仅在独立测试目标启用内存仿真，继续验证既有状态机与取消行为；生产程序不启用该宏。

生产源码快照 `244857f` 的完整 Windows 构建 [40823908906](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40823908906)通过上述 41 项测试及包内 GUI/API 检查，但后续[真实键鼠复核 40826710888](https://github.com/john2000smith7-del/SerialCtl/actions/runs/40826710888)发现电源监测页采样下拉框仍可操作：切换后被新的服务门禁拒绝并弹出模态提示，使下一次键盘输入失去原目标。这次运行测试脚本为 `aa25189`，与程序 `244857f` 的生产源码完全相同，仅证据导出工作流有差异。现将采样选择器随功能开关禁用，并在原生 GUI 和打包 GUI 检查中断言其禁用状态；真实键鼠检查保留，必须由修正后的匹配构建复测。先前的失败不作为通过记录。

## 升级兼容性

本分支相对原 main `5385e8bde1e60ee9c1babce9d1da54e8ee6cb372` 的 `src/update/`、`tools/new_update_feed.py`、`scripts/package.ps1`、`scripts/smoke-update.ps1`、`docs/package/update.ini` 和活动签名身份均未改变。保留：

- 同一静态目录的完整 ZIP 与内嵌签名 `update.json`，原 `[update] url=` 及默认地址。
- 启动后台检查、原信任根验签、更高版本提示确认、完整 ZIP 下载与逐文件校验、空闲安装和重启。
- 配置、命令、日志和驱动保护，以及原安装事务备份、健康握手和失败恢复。
- 原公钥 SPKI SHA-256 `196b703ac1274da483936513794f0c03eb7be806c302db4d932b30378a78a21a`。原身份的 V2.0.0+ 客户端可以跳版本；曾安装历史替换公钥的 V2.0.4 客户端需要另行迁移，V1.10.0 及以前需手动部署一次支持新格式的版本。

本次仍为 V2.0.10，已经运行 V2.0.10 的机器不会因重编译而自动更新，需要手动替换一次；后续自动升级须提高产品版本并用原身份对精确配套 ZIP 签名。更新客户端、安装器、完整发布 ZIP 的临时测试签名提取、Python 发布工具和真实窗口升级冒烟继续列入完整 Windows 构建；临时测试签名不能作为正式部署签名。

记录中的活动私钥 `/workspace/.serialctl-signing/serialctl-update-v2-rsa2048.pem` 在当前工作环境不存在，活动身份也没有仓库加密备份。本次不创建新密钥、不更换信任根、不将历史替换身份冒充原身份、不提供未签名或测试签名的部署 JSON。因此编译包可手动部署，正式自动更新双文件交付仍需原身份的授权签名过程；此限制不影响源码合并或客户端后续升级能力。本次不创建 Release、tag 或更改线上更新源。
